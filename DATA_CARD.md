# DATA CARD — Kaam-Vaani datasets

Every dataset the system reads, with its source, size, licence,
and known issues. Nothing here contains real user data.

## 1. RAG knowledge base — snapshot v2 (`data/kv_rag_snapshot_v2.jsonl`)

- **Size:** 1,048 chunks. By topic: occupation 974, rights 27,
  scam 19, skilling 13, wages 8, courses 3, employment 2,
  schemes 2. All chunks English.
- **Composition:** 974 O*NET occupation chunks (from the in-app
  catalogue, no network) + 19 web chunks (official Indian
  government home pages: SWAYAM, NPTEL, NSDC, DGT, NQR, NCS,
  myScheme, TN Labour, ILO India) + 47 Wikipedia chunks
  (fallback where official sites were JS shells, 403s, or
  unreachable) + 8 central-sphere minimum-wage chunks (Step 7B).
- **Licences:** O*NET CC BY 4.0; Wikipedia CC BY-SA 4.0;
  government pages are public information. Every chunk stores
  source URL, title, date, licence, language.
- **Wage data:** Labour Bureau VDA order File No. 6/1/2026-VDA
  (30 Sep 2026, rates from 1 Oct 2026, next revision 1 Apr
  2027). Scanned PDF, OCR'd (RapidOCR, 150 DPI); all 52
  basic+VDA=total sums re-added (0 mismatches); structured copy
  in `data/kv_wage_tables_2026-10.json`. **Central sphere only.**
- **Known issues:**
  - Tamil Nadu STATE wage rates are ABSENT (official G.O. PDFs
    all 404; aggregators conflict ₹8,500 vs ₹13,823/mo and were
    not ingested).
  - e-Shram has zero coverage (site is a JS shell; no Wikipedia
    article exists).
  - The EPFO article carries two different wage ceilings
    (₹15,000 historical, ₹25,000 current) — kept as-is, the
    contradiction recorded in SOURCES.md §5.4, not resolved by
    guessing.
  - Web chunks are home-page text only (site sub-pages were
    mostly JS shells).
  - Snapshot v1 (1,040 chunks) is kept for reference; v2 adds
    only the wage chunks + one re-fetched ILO page.
- **Refresh:** bump `--version` on `python -m scripts.ingest.run`
  (never overwrite in place), update SOURCES.md, re-run the
  eval, commit snapshot + meta + docs together.

## 2. Golden evaluation set (`eval/kv_golden.json`)

- **Size:** 189 cases — 55 profile, 115 retrieval, 19 refusal.
- **Origin:** hand-written by the builders in Stage 2 / Step 7A,
  in realistic voice style across English, Hindi (Devanagari +
  Roman), Tamil (script + Roman), and noisy English.
- **Purpose:** the quality bar. Every retrieval/ranking change
  must re-run it (`python -m eval.run_kv`).
- **Known issues:** hand-written, not sampled from real users —
  it measures the builders' idea of realistic questions. No
  real-user queries have been collected (none exist yet).

## 3. Occupation catalogue (`data/catalog/occupations.json`)

- **Size:** 974 occupations, from O*NET (CC BY 4.0).
- **Note:** documents say "Preparation level: N", not "Job Zone"
  — the O*NET label injected the word "job" into all 974 chunks
  (see EVAL_REPORT.md).

## 4. Seed data (sample employers, listings, workers)

- **Size:** 40 listings, 10 sample workers, 5 employers,
  3 coordinators, 5 fake listings — all labelled "sample data".
- **Purpose:** pilot/demo content and test seeding. The 5 fake
  listings exist to exercise the scam checker.
- **Deletion:** `delete_sample_data()` removes sample workers
  only (pinned by test); real rows are untouched.

## 5. LoRA training data (generated, not trained on)

- **Size:** 55 gold profile cases → 49 train / 6 validation
  JSONL rows, generated by `lora_data.py` from the gold set +
  the production profile-extractor prompt.
- **Status:** generated only. Training was never run; the
  notebook was never executed. No model exists from this data.

## 6. Helplines (`data/kv_helplines.json`)

- **Size:** 2 entries — 1930 (National Cyber Crime Helpline,
  verified from PIB releases, 06 Apr 2022) and 1514 (NCS
  helpline, from the NCS KB chunk). See SOURCES.md §5.6.
- **Rule:** no helpline number is added without a source entry.

## 7. What is NOT in the repo

- No real user data, no real worker profiles, no real employer
  data, no real video clips (the video tests use synthetic
  ffmpeg clips), no real phone numbers (test numbers are
  obviously fake), no credentials. The dev database
  (`data/career_guidance.db`) holds seed + test data only.
